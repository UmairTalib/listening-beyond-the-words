### Added

- A table writer for `reports/` (`reports.write_table`): CSV at full precision, written all or nothing and returned with its SHA-256, refusing a column named as an ID (in any case and spelling, such as "Session ID") or by a number or a segment ID, a cell that holds a segment ID, no value or an infinite number, an index other than 0 to n − 1, and a file that exists already.
- The evaluate job (`scripts/evaluate.py`, CPU job `scripts/slurm/evaluate.sbatch`, 30 min), as fixed in `docs/pilot_analysis.md`. It refuses to run outside a Slurm job, from a checkout with uncommitted changes or at any commit but the newest `v0.1.x` tag of its clone, and with installed code of another version than that tag's; it has no `--allow-dirty`. It reads `configs/pilot/evaluate.yaml` refusing a key given twice (`config.read_settings`) and checks every pin before it reads anything: each kept run's `run.json` and `scores.parquet` by their SHA-256 and its record, each kept run the earliest done run of its fold-run that counts (a later one is reported), and the pinned set must be one of the protocol's versions. It reads the labels with their PHQ-8 totals (`clips.load_pinned_labels` with `phq8_total=True`), each label checked against its total, and draws the bootstrap's resamples before any score is read. Then come checks F1, F2 (per CPG run and pooled), F4 and F5, from records only, a record of F4 or F5 that does not say pass being refused; the zero-shot and B0 scores, each run's holding exactly its test fold's segments of `x0` and `rev` with every z finite, and check F3; and B1's and CPG's scores only once all five checks pass. A failed F2 or F3 writes the checks and the zero-shot and B0 numbers, says so and stops, with no Δ and no outcome. The job writes `checks.csv`, `fold_values.csv`, `summary.csv` and `outcome.csv` through `reports.write_table`, a value that cannot exist written as text such as "not available (cut: no B1)", and a `run.json` with the pins, the draws' seed, stream, redraws and SHA-256, the two values that the framing line compares, and aggregates only. `--trial` reads only the zero-shot scores and B0's round 1, with no difference, no F3 and no rule. `scripts/list_runs.py`, on a login node, reads only the training runs' `run.json` files and prints the `runs:` block that pins the kept runs, the earlier of two that share a fold-run, with every run folder left out and why. The job's tests run it end to end on a light workspace written in code, inside `make check`, and check every interval and standard error against an independent bootstrap of the recorded draws. The conventions describe the job, its folder and its tests, and the release step now sets the next release plus `.dev0`.

### Changed

- 2026-11-26: the rules of the pilot analysis are fixed in the new `docs/pilot_analysis.md` and `configs/pilot/evaluate.yaml`, every value with its source, before any AUROC of any arm is computed, because the pilot protocol leaves seven points of the analysis open. The page fills only those points and changes none of the protocol's rules, and the protocol page stays frozen. It comes after the first test scores existed but before any number from them used a label, so the rule that still holds is the protocol's: nothing is tuned after results that use the labels. Participant scores and fold AUROCs are exact fractions; every mean over fold-runs gets an 80% and a 95% percentile interval from one set of paired draws with a seed of its own (109), and each difference a bootstrap standard error; the checks that read no score come first, the zero-shot and B0 scores with check F3 next, and B1's and CPG's scores are opened only once all five checks pass, a failed F2 or F3 stopping the analysis before any Δ; each kept run is pinned by its folder and the SHA-256 of its scores and its record, and the pinned set must be one of the protocol's versions; a trial reads only the zero-shot scores and B0's round 1; and the analysis runs only from the release that holds its code. The docs index lists the page, and the glossary gains "Bootstrap", "Percentile interval" and "Spearman correlation".
- The word check's AUROC and percentile code (its pair wins, count-weighted fold AUROCs and NumPy linear percentiles) moved to `evaluation.py`, which the analysis shares; the word check computes and prints the same, bit for bit.
- The release-tag ordering of the train job (`RELEASE`, `release_number` and `newest_release`) and its first runs (`FIRST_RUNS`, `is_first_run`) moved to `runinfo.py`, which the analysis shares; the train job allows and refuses the same runs, with the same messages.

- Interviewer detector, first part: spectral fingerprints of short sound events, the search for each event's best match in every other session, and a GPU job that checks the premise (gate P1) and builds the template libraries of the interviewer's recurring clips (gate P2).
- Interviewer detector, second part: a GPU scan of every session with every template (normalised cross-correlation, on all cells and on the quiet frames), pitch decoys that set the threshold, zones, and a job that checks gates D1-D4 with planted copies and reports what the zones would cost by class and gender.
- DAIC-WOZ transcripts: a script on OMNI takes each session's human transcript, with the interviewer's lines and their times, out of the downloaded official archive. Each word is kept or dropped, with every condition it fails and one cause. Kept words get part keys, so that a part ends at a new line, a dropped word, an interviewer turn or an interruption, and, in the sessions without interviewer turns, at a new participant turn.
